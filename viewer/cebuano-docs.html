A candidate-ranking method, not a pronunciation authority

The system screens published Philippine FDA brand and generic names for possible look-alike/sound-alike relationships. It preserves the official spelling and creates several documented pronunciation hypotheses. It does not decide what a speaker “really meant,” identify a medicine from speech, or prove clinical risk.

Human review remains required: confirm the exact published name, ingredient, strength, dosage form, route, registration, and clinical context before relying on a candidate.

How a registered-name pronunciation profile is built

1. English-derived route

The engine prefers an exact CMU Pronouncing Dictionary entry. For an unknown token, eSpeak NG applies its English exception dictionary and surrounding-letter rules. Optional Epitran English/Flite and an emergency high-cost spelling path remain later fallbacks.

2. Cebuano direct-reading route

Epitran ceb-Latn is applied as a direct reading of the written token only when every unit is covered. This is not a model of a Cebuano speaker’s English accent.

3. Explicit nativized route

If a raw direct reading cannot cover letters such as f, v, x, z, or q, the engine can make a separately labelled, higher-cost compatibility form such as f→p or x→ks, then checks coverage again.

4. Relevant local adaptations

The browser emits one deterministic local vowel reading whenever English G2P succeeds, including a same-display confirmation when no vowel changes. Its monotonic alignment can skip silent written vowels and recognize a vowel-like y. A rare incomplete alignment preserves unmatched English phones and is visibly marked partial. It never enumerates every combination. Separate consonant candidates use one bounded rule such as /f/→/p/.

What contextual G2P and Epitran do—and do not—say

eSpeak NG handles the large English spelling-to-sound problem with a dictionary plus ordered rules that inspect nearby context; the project does not try to enumerate every value of five vowel letters. Optional Epitran eng-Latn is Flite-backed, while ceb-Latn provides a separate Cebuano orthographic direct-reading seed. The latter cannot be described as “how Cebuano speakers pronounce English.” Every selected path retains IPA, source, evidence, coverage, rules, cost, and stress availability.

topic

An English dictionary path can display as tapik, while a fully covered Cebuano direct-reading path can display as topik. The two paths coexist.

model

An English dictionary path can display as madel, while a Cebuano direct-reading path can display as model. Neither is declared universally correct.

binary

The browser aligns i | ar | y with /aɪ | ɚ | i/. It therefore keeps English bayneri, adds the one-rule written-a hypothesis baynari, and keeps direct binari separate. The written-a rule permits a, o, or ey—never e or i.

Stress

Stress contributes only when both selected paths supply it. Epitran paths have unknown stress; the system does not invent a fixed penultimate-stress rule.

How a sound-alike score is chosen

For each profiled pair, the batch engine first ranks route pairs by a cheap cost-aware whole-path score. It performs detailed IPA-phoneme and IPA-syllable comparison only on a small cost-ranked beam plus a few raw-score audit leaders, then retains both the raw best match and the cost-adjusted selected match. Full profiles are staged for phonetic-only recall and selected review rows rather than every spelling candidate.

cost-adjusted score = max(0, raw similarity − fixed penalty × (path cost A + path cost B))

This prevents two high-cost fallback paths from automatically winning just because their display spellings are identical. The review record shows the winning display forms, IPA, route, evidence, and costs so a reviewer can see why a pair surfaced.

Candidate blocking includes ordinary spelling keys and coarse IPA-derived keys. A phonetically close but orthographically distant pair can therefore reach full comparison, while the final result remains a screening signal rather than a diagnosis.

Batch data versus browser G2P

The batch Python engine is authoritative for registered-name profiles and saved review-pair scores. The pronunciation explorer shows the exported batch path provenance for a registered name.

The free-form lab, typed matching, product suggestions, and chat name resolution use bundled Phonemizer.js/eSpeak NG contextual G2P. They no longer use a fixed example-word table or blanket vowel-merging paths. Browser results remain generated hypotheses and cannot be presented as CMUdict evidence or a speaker-validated result.

Limits and required validation

  • Cebuano speakers vary by dialect, exposure to English, setting, and medicine familiarity.
  • CMUdict, eSpeak NG, and Epitran supply sources or baselines, not local speaker evidence.
  • Route costs and feature weights are fixed experimental parameters, not clinical probabilities.
  • High scores can be false positives; numeric strength/version differences must remain visible.
  • “Verified LASA” and “false positive” labels require documented human review.
